## Contracts

- Runtime data lives in a private project output directory, outside the public package. JSON paths are relative to that data root; path escapes are rejected.
- Character approval records identify a human statement and its time. Automation validates presence/structure, never invents approval or certifies likeness.
- Planned reference images and actual tool arguments are separate. A path written in a prompt is not evidence of an image being supplied. Unsupported reference input blocks identity-dependent generation unless the user explicitly accepts a recorded downgrade.
- Each attempt has its own run ID, prompt, invocation evidence and output. Edits create new attempts linked to parents. Existing image files are never regenerated by the helper scripts.
- Generation statuses distinguish planned, running, generated, failed and unknown. Unknown outcomes require reconciliation before retry. QA and human review remain separate from generation status.
- PPT planning and sample confirmation gates remain intact; approved batches do not ask again per page. Contact sheets are review aids, not approval evidence.
